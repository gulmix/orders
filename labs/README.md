# labs

Учебные задачи, которые не являются частью сервиса.

HTTP-сервер на голых сокетах, пул воркеров, игрушечный движок хранилища,
защищённый канал из криптографических примитивов — всё это нужно, чтобы
понять, как оно устроено изнутри. В работающем `orders` такому коду делать
нечего, поэтому он живёт здесь.

Правила простые:

- код решает задачу `orders` — он в `internal/`, и вы должны уметь показать,
  кто его вызывает. Упражнение — он здесь;
- `make check` проверяет `labs/` наравне с сервисом: тот же линтер, те же
  тесты под `-race`, тот же CI и то же ревью;
- ни один пакет сервиса из `labs/` ничего не импортирует. Удалите каталог —
  `orders` обязан собраться и пройти тесты;
- в модуле 10, когда сервис поедет в гексагональную структуру, `labs/`
  не участвует.

Каждая задача — свой подкаталог со своим пакетом:

```
labs/
  workerpool/   пул воркеров, его тесты и бенчмарк
  stats/        счётчик и тесты на гонки
  conns/        TCP-сервер и клиент для экспериментов с соединениями
  secchan/      защищённый канал из криптографических примитивов
```

Имена — предложение из заданий, а не требование. Задание модуля всегда
говорит, куда класть код, и «положил не туда» — это замечание на ревью.

Этот файл можно править и дополнять: он ваш, как и всё остальное
в репозитории после модуля 0.
