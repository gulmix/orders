# orders

Сквозной проект курса по бэкенду. Один сервис, который вы ведёте от первого
модуля до последнего.

Репозиторий — шаблон. Нажмите **Use this template → Create a new repository**,
назовите `orders` и дальше работайте только в своём. Можно выбрать **Private**.

## Старт

```bash
git clone git@github.com:<ваш-логин>/orders.git && cd orders

make tools     # поставить golangci-lint нужной версии (один раз)
make check     # линт + тесты: на чистом шаблоне должно быть зелено
make run       # сервис на localhost:8080
```

```bash
curl -s localhost:8080/healthz
# {"status":"ok"}
```

Добавьте преподавателя в **Settings → Collaborators**, иначе не получится
запросить ревью.

## Команды

| Команда      | Что делает                                                 |
| ------------ | ---------------------------------------------------------- |
| `make check` | **Главная.** Ровно то же, что гоняет CI                     |
| `make test`  | Тесты под `-race` с покрытием                               |
| `make run`   | Запустить сервис локально (подхватит `.env`, если он есть)  |
| `make lint`  | Только линтер (`make lint-fix` — с автоисправлением)        |
| `make fmt`   | Отформатировать код                                         |
| `make cover` | Открыть отчёт о покрытии в браузере                         |
| `make help`  | Все команды                                                 |

Всё, что проверяет CI, запускается локально одной командой. Если что-то
ловится только в CI — это баг конфигурации, напишите в чат.

## Структура

```
cmd/orders/            composition root: собрать зависимости и запустить
internal/
  routes.go            карта URL целиком, в одном файле
  config/              конфигурация из окружения
  requestid/           сквозной идентификатор запроса
  middlewares/         request id, лог, recover
  servers/http/        http.Server, таймауты, graceful shutdown
  controllers/http/
    health/            проба /healthz — образец контроллера
    response/          единый формат ответа и коды ошибок
    order/             ← ваше: хендлеры заказов
  services/order/      ← ваше: сценарии
  repositories/order/  ← ваше: хранилище
  models/order/        ← ваше: домен
```

Зависимости идут в одну сторону: `controllers → services → repositories →
models`. Домен внизу и не знает ни о ком; всё, что снаружи, знает о нём.
Это единственное правило раскладки, которое нельзя ломать — на нём держатся
следующие модули. Сама разбивка по слоям — осознанная стартовая точка,
к ней мы вернёмся в модуле 10.

Пакеты, помеченные `← ваше`, пустые: в них лежит только объявление пакета
с описанием, что туда класть. Файлы внутри создавайте как считаете нужным.

## Конфигурация

Только через переменные окружения. Локально удобно держать их в `.env`
(`cp .env.example .env`) — его подхватывает `make run`. Сам сервис никаких
файлов не читает.

| Переменная                | По умолчанию | Назначение                          |
| ------------------------- | ------------ | ----------------------------------- |
| `ORDERS_HTTP_ADDR`        | `:8080`      | Адрес HTTP-сервера                  |
| `ORDERS_SHUTDOWN_TIMEOUT` | `10s`        | Таймаут graceful shutdown           |
| `ORDERS_LOG_LEVEL`        | `info`       | `debug` / `info` / `warn` / `error` |

## Сдача

Задания приходят в чат курса. Один модуль — одна ветка — один PR в ваш же
`main`:

```bash
git switch main && git pull
git switch -c module-0/orders-crud
# ...работа, коммиты...
make check                              # зелено ДО пуша
git push -u origin module-0/orders-crud
gh pr create --base main
```

Имя ветки, заголовок и текст PR — на ваше усмотрение. Единственная просьба:
напишите в теле, чем проверить, что работает.

Дальше: зелёный CI → ссылка на PR в форму сдачи → ревью → после апрува
мержите сами. `main` — всегда последнее сданное состояние, с него начинается
следующий модуль.

Шаблон отдаётся один раз и не обновляется: всё, что появится в проекте после
модуля 0, пишете вы.
